## Feedback Inbox

### Bug

- 翻译缺少语言包时，点击下载后系统下载弹窗会持续停留在最前层；除非用户手动点击“完成”，否则弹窗不关闭，但弹窗内进度条不更新，和系统设置中的真实下载进度不一致
- 在“跟随鼠标”模式下，点击弹窗内按钮后，弹窗会根据这次点击位置重新定位，导致操作过程中窗口发生跳动
- 翻译结果出现“当前版本的系统翻译优先支持中文和英文文本，其他语言暂不自动翻译”的提示；需确认这是语言支持范围限制、语言识别策略问题，还是中英混排内容触发了误判
- 翻译结果会出现意外换行或分段；例如原文被识别为两行时，译文也被拆成两个独立段落，影响阅读和复制体验
- 翻译状态疑似存在不稳定或卡住问题；同一个词汇曾翻译成功，但重复测试时可能一直转圈，先去翻译其他内容成功后，再回来翻译这个词又恢复正常
- 刚安装且尚未授予权限、也没有截图内容时直接打开窗口，底部按钮区域的间距和对齐表现异常，空状态布局不正确
- 在“阅读优化”下手动增删文本后，再切到“原始文本”时仍显示初始 OCR 内容，两个模式各自保留独立草稿会带来明显割裂感；后续需要明确是做跨模式同步、单一编辑源，还是提供更清晰的模式提示（当前倾向「单一编辑源」，并与上方「功能 toolbar」重设计一并推进——引入选词后“编辑”地位下降，更易论证单一编辑源）
- 结果面板的正文区和翻译结果卡片虽然已按设计稿拆层，但仍需在真实 OCR 长文本、短文本和错误态下再做一轮视觉回归

### Optimization

- 优化序列符号识别稳定性；同一内容重复截图时，列表编号或项目符号的识别结果会出现波动
- `OCRService` 的 `paragraphSeparator`（OCRService.swift:263）两个分支都返回 `\n`，是死逻辑；与上方“译文意外换行/分段”反馈相关，需确认段落间是否应改为输出 `\n\n`
- `OCRService.recognizeText`（OCRService.swift:26）对原图与增强图串行跑两遍 Vision，两路相互独立，可用 `TaskGroup` / `concurrentPerform` 并行以减半识别延迟
- 取消截图预览区的最低高度限制，让较矮截图时的整体布局更紧凑
- 截图过程中按 `Esc` 取消时，不要再唤起结果窗口，减少取消路径上的额外打扰
